# N1: held-out locate after drift (draft)

Benchmark protocol section 3.5, row N1. Status: author draft (`n1.draft.jsonl`), not yet blind-labelled or
adjudicated; nothing has been run on it.

## Purpose

Held-out data for the `locate` site (`locate --recorded LINE --intent I --risk R`), and the write row D3. Each
item records one element on a "before" page of a synthetic site. The candidates come from a drifted "after" build
of the same site. The question is which current candidate is the recorded element, or `none` when it was removed.
None of these pages were in a refsure fit.

## Composition (matches row N1 exactly)

| condition | what changed between before and after | write | read | gold |
|---|---|---|---|---|
| edited | the element's label is reworded in the same language (synonym copy) | 125 | 50 | candidate |
| moved | the element moves to another section or landmark, same label (main to main 99, main to sidebar 28, sidebar to main 10, header to footer 11, header to navigation 8, navigation to header 7, footer to main 6, navigation to footer 6) | 125 | 50 | candidate |
| translated | the whole page is translated; 42 of 175 also reword the element in the new language | 125 | 50 | candidate |
| rehashed | a rebuild: ids and classes regenerated, plus a component swap (button to link 84, link to button 42, checkbox to switch 2, searchbox to combobox 2) or the section wrapped in a named region (45) | 125 | 50 | candidate |
| removed | the element is gone; 72 keep a named look-alike nearby (the template's `near` element), 8 have none | 40 | 40 | `none` |
| total | | 540 | 240 | 700 candidate, 80 `none` |

So gold is a candidate for 500 write and 200 read items, and `none` for 80 items (40 write, 40 read), as the row
asks. `danger_eligible` is true on the 80 `none` items. That is below D299 by design (protocol 3.6: exact bound,
not part of the verdict).

Bases: 196 (44 translated, 152 drift), at most 4 items per base. A base is one site instance: one before page and
one after page (`pages/BBB/before.html`, `pages/BBB/after.html`, 392 pages, all distinct, 3.5-5.1 KB). In a drift
base, the after build carries all of its items' changes at once (up to 4 different conditions), the way a real
release would. Items prefer distinct sections. A section wrapped in a region holds only one item and receives no
moved element, so a section-wide change touches one item only. The group key is `base`.

on the page when the gold is edited, moved, translated or removed. Edited labels drop the recorded words ("Mark as

heading as well as the label. The removed items keep the near look-alike, so the fair answer is `none` even though

## Generator

    node tools/bench/sets/gen/n1.mjs

Plain Node, no dependencies, seed `refsure-bench-n1-20261016`. It deletes and rewrites `n1/`, writes
`n1.draft.jsonl`, and prints the counts. Two runs give byte-identical output. Per base it drafts element choices
and keeps the first draft that passes these checks:

- The recorded line is nowhere on the after page, so refsure's code would not settle it.
- Each page has one element per role and label (folded).
- No other element on the after page carries the recorded label.
- Each page has at most 20 candidates.
- The condition shows in the line: edited and translated change the label, while moved and rehashed keep the
  label and change the place or the role.

When a base's planned template cannot carry its slots, the next template in turn is used. That is why the template
counts differ (56-68).

Checked with a throwaway checker: every gold and recorded selector matches exactly one element, whose accessible
name equals the stated name. The checker also confirmed the per-condition and per-risk counts above, at most 4
items per base, 392 distinct pages, and that no page loads anything external (no `http(s)://` and no `src=`). Links
are root-relative paths. None of the forbidden company names appears.

## Known limits

- `input.recorded` and `input.lines` are the author's emulation of refsure's line format v1 (places navigation,
  main, form, region, then the last heading in scope), listed in page order. The native capture (P2,
  `tools/calibrate/orca-native.ts`) replaces them with the lines refsure's own snapshot gives. It takes the
  recorded line from `recorded_page` through `recorded_ref`, and the candidates from `page`, ranked and cut to 20.
  Gold is mapped through `gold_ref`. `read-refsure-set.ts` has no `locate` branch today, so P2 must add one that
  reads `recorded_page`, `recorded_ref` and `input.intent`. The draft expects no item to be settled by code, and the
  capture's dry run confirms or corrects that (X5).
- Ids and classes never reach the model, because a v1 line carries none. A pure id rehash would leave the recorded
  line verbatim on the page, and code would settle it. So `rehashed` pairs the regenerated ids and classes with a
  rebuild change that the line shows: a component swap, or a named region around the section. A move inside one
  section would leave the line unchanged in the same way, so `moved` always crosses sections.
- Pages hold 15-20 candidates, so the 20-line cut never drops the gold (X2 is not exercised). Real pages are
  larger, and their shortlist depends on ranking.
- Each template's vocabulary has 17-20 elements, so the same element appears in several bases under different
  conditions, languages and builds. The independence key is the base. Element reuse across bases is a mild
  correlation that the base clustering does not capture.
- Five languages, no ru. Step intents are English for every item.
- 80 `none` items are below D299, as 3.6 states. All 80 are `removed`. No `none` item comes from translation or
  from a heavier rebuild.
- `why` sentences are generated from the vocabulary. Whether each near look-alike is truly a different action is
  the vocabulary author's judgement, to be checked by the blind label and adjudication.

## Blind label and adjudication (2026-10-16)

Final set: `n1.jsonl` (779 items) = `n1.draft.jsonl` minus n1-0745, rows byte-equal otherwise; adjudication
changed no gold, so no item carries `adjudicated`. Detail per disagreement: `n1.adjudication.md`.

- Labeler: `gemini-3.8-flash-high` through `agy` for all 780 items (A2), 17 batches of at most 49 (A2's 50 cap),
  each in an empty directory holding only that batch's blind file. 5 batches needed a second attempt (4
  "interrupted", 1 malformed answer); no 503, no OpenRouter fallback. Every label selector matches exactly one
  element on the after page.
- Blind agreement, raw (same element, or both `none`): 775/780 (99.36%). Gold candidate 697/700, gold `none`
  78/80; write 537/540, read 238/240; edited 173/175, moved 174/175, translated 175/175, rehashed 175/175,
  removed 78/80; en 283/285, uk 114/116, de 116/116, es 132/132, pl 130/131.
- Disagreements: 5. Kept draft 4 (n1-0251 and n1-0267: the label picked the planted near look-alike, which was a
  separate element before the change; n1-0435 and n1-0471: "Help" became "Documentation" with the same `/docs`
  target in the same header slot). Took label 0. Dropped 1 (X8): n1-0745, a booking button moved from one
  flight card into another, where "same element" and "same action" part ways.
- After adjudication: 779 items settled; the blind label matches the final gold on 775/779 (99.49%).
- Flagged, not changed: n1-0113 and n1-0614 have the same card-to-card move in the travel template, but the
