# n6

Benchmark protocol 3.5, row N6, as amended by A1. Draft only: not yet blind-labelled, adjudicated, captured or frozen.
Files: `n6.draft.jsonl` (800 items), pages `n6/pages/001.html`…`800.html` (one page per item, named by item id).

## What it measures

The `presence` site (`wait-for --expect "<text>"`): given an expectation, the page URL and the page text, is what the
expectation describes on the page. Gold is `true` or `false`; only the yes edge acts (`present`). The set is held-out
data for the presence row (D5, Q1, Q5) and the false-`present` danger cell (D299): the async result declared arrived
when it has not.

True 440, false 360 (all false items `danger_eligible: true`). Bases 220: 180 hold 2 true + 2 false items (two
different false conditions), 40 hold 2 true items; so a base holds at most 4 items and at most 2 danger-eligible ones
(danger m = 2, 180 danger groups). Items are shuffled with a fixed seed before ids are given.

Expectation kinds (`exp_kind`): `main` (the record), `res` (its result), `num` (its number), `status` (its state).
Per condition: paraphrase main 57 / res 53; translated main 38, res 38, status 34; number_format num; status_reached
status; loading main 15, res 16, num 14; queued and partial res; wrong_entity main 10, res 13, status 9, num 13;
near_miss num 30, status 15; negation status (a refused record is still shown, so only its state is denied); login
main 23, res 22; error main 19, res 26.

Hard cases on purpose: 108 true pages carry an unrelated warning banner (password expiry, sync failure, maintenance);
true pages list a near-twin record in the sidebar (shop); wrong_entity and near_miss pages are otherwise complete
and correct; negation notes reuse the expectation's words; 102 non-translated items pair an English expectation with a
non-English page.

## Item fields

`id, page, site ("presence"), lang, expectation_lang, source ("synthetic"), condition, base, template, kind,
exp_kind, at, expectation, input {expectation, pageUrl, page}, input_provisional, gold, alt ([]), danger_eligible,
why, evidence, absent`.

- `input` is refsure's `PresenceInput`. `pageUrl` is the served path `at` and `page` this generator's own text reading
  (`input_provisional: true`); the native capture (P2) replaces both with what refsure reads through Orca, mounting
  each page at its `at` (login pages at `/login?next=…`). `expectation` is final.
- `evidence` lists strings the page must show and `absent` strings it must not (the record's ref on loading, login,
  error and wrong_entity pages; the result on queued, partial, negation pages; the expected number on near_miss).
- No item sets `--text` or `--url`, so refsure's present-by-code rule never fires and no item is settled by code at
  capture (X5); X1 does not apply to presence. The danger pool stays 360 (P3b floor 345).

## Generator

    node tools/bench/sets/gen/n6.mjs

Plain Node, no dependencies, seed `refsure-bench-n6-20261016`; two runs give byte-equal output. Files: `n6.mjs`
(plan, expectation language, output), `n6-cond.mjs` (the 12 conditions), `n6-page.mjs` (table, badge, progress
list, loading and sign-in mains, shared scenario facts), `n6-fmt.mjs` (number and date styles, near values, near-twin
refs), `n6-lang.mjs` (wording and near-twin names in 5 languages), `n6-templates.mjs` and `n6-tpl-*.mjs` (one per
template). Page chrome, error pages, the session box and decoy notices are reused from `n5-shell.mjs`, `n5-lang.mjs`
and `n5-lib.mjs`. All brands, people and places are invented; e-mail addresses use `example.test`; links are relative;
no page loads anything (no script, image, font or external stylesheet).

Checks run on the draft (throwaway checker outside the repo): counts per condition, gold and language as above; every
base <= 4 items, <= 2 false, one template; 800 page files, no two byte-equal; largest page 5.6 KB; no `http(s)://`,
`src=`, `url(`, script or forbidden company names in pages or items; every `evidence` string present and every
`absent` string missing in the page text; every quoted string in `why` found in the page or the expectation; no
paraphrase expectation appears verbatim in its page; every translated item has two languages.

## Known limits

- Two true items of a base show the same record in the same state; their pages differ only in the banner, the update
  time and control ids, and their expectations differ. The group is the base.
- Login and error pages (90) are easy for a careful reader; the hard false items are wrong_entity, near_miss, partial
  and negation.
- Every template uses one record layout (table, badge, progress list); the sites differ in chrome, wording, numbers
  and result kind, not in deep structure. The progress list spells out all steps (open ones marked `○`).
- uk, de, es and pl copy was written by the author, not reviewed by a native speaker; names in uk/pl expectations are
  set in apposition (`(автор: …)`) to avoid declension.
- Blind agreement and adjudication results are added here after P1 (3.5).

## Blind label and adjudication (2026-10-16)

- Labeler models: `google/gemini-3.1-pro-preview` through OpenRouter for all 800 items; no `gemini-3.8-flash-high`
  label exists for N6. `agy` answered "Individual quota reached" (reset in 2h12m) on the first attempt of every
  batch, so each batch went to A2's OpenRouter fallback under the 30-minute rule (N6 is synthetic, no X4 item).
  32 batches of 25, all parsed with ids matching in order.
- `n6.blind.jsonl` holds only `id`, `question` (the presence site's wording with the expectation filled in) and
  `page` (page HTML); no gold, `why`, `condition` or note.
- Blind agreement, raw: 799 of 800 (0.9988). By gold: true 440/440, false 359/360. By condition every one agrees
  fully except `near_miss` 44/45. By position in batch no degradation (11-15: 159/160, every other band 160/160).
- Adjudication (`n6.adjudication.md`, a fresh Claude Opus 5.5 agent): keep draft 0, take label 0, drop 1. n6-710
  (near_miss, "The upload of … has completed" on a page whose State is "Checking for viruses" but whose progress
  list ticks "✓ Uploading") reads true or false depending on what "upload" means; dropped under X8.
- After adjudication the blind labels agree with the final gold on 799 of 799 (1.0000); the final gold is settled on
  799 of 800.
- Drops (X8): n6-710. `n6.jsonl` (799 items, sha256
  ffcb11e5012ef9b4ea08967420ba56fa9ea0cda2c5465994917e3155f0cbf5cc) is the draft without that line; no item carries
  `adjudicated`.
- Limits: the adjudicator is the author's model family (T3); the labeler is the A2 fallback model, not A2's primary;
  near agreement on one labeler is not proof that the hard false items are hard for a model arm.

## Floors (3.6)

Pre-capture counts; P3 re-derives them on the post-capture file. Presence is not a candidate site (X1 does not
apply) and no item sets `--text` or `--url`, so none is expected to be settled by code (X5).
- E99 (presence, yes edge): 440 true x 0.80 = ~352 acted; n_eff ~306 at 3.6's deff 1.15: holds (>= 299), unchanged
  by the drop.
- D299 danger: 359 false items, n_eff floor(359 / 1.099) = 326: holds (>= 299).
- A1 / P3b floor for N3-N6: danger-eligible pool 359 >= 345: holds, with 14 items of reserve.
