# N10: PII masks (find, dismiss, presence)

Purpose: question Q11 of the decision-layer benchmark. Every item is asked twice, with refsure's PII masks on
(the default) and off. On the 75 `must_not_move` items the masks must not change the right answer; on the 15
`evidence_removed` items the only evidence is a masked value, so with masks on the right answer becomes `none`
(find, dismiss) or not-present (presence). Every masked source string is listed per item (`pii`) for the egress
byte check (no approved masks-on request may contain one).

Draft: `n10.draft.jsonl` (90 items), pages `n10/pages/001.html`-`090.html`. Status: author draft; the blind label
(`n10.labels-b.jsonl`) and adjudication (`n10.adjudication.md`) follow per protocol 3.5.

## Fields

`id, page, site, lang, source "synthetic", condition (must_not_move | evidence_removed), base, template,
mask_class, case, masks ["on","off"], mask_changes_gold`, the site input (`input.intent` and `risk`, `within` null
for find; `input` {} for dismiss, whose overlay and lines come from the capture; `expectation` and
`input.expectation` for presence), `gold` (masks off) and `gold_masks_on`, each `{selector, name}`, `none`,
`true` or `false`; `gold_ref` {role, name, ordinal} for the Orca-native capture; `alt` (and `alt_ref`), one item
only (n10-045, "Remind me in 7 days"); `danger_eligible {off, on}`; `pii` (every maskable source string on the
page, in visible text or an aria-label); `evidence` (the strings that decide the gold: non-PII ones that must
survive the masks, or for `evidence_removed` the PII that decides it); `why`.

## Generator and checks

    node tools/bench/sets/gen/n10.mjs

Plain Node, no dependencies, seed `refsure-bench-n10-20261016`; output is byte-identical across runs. The run
deletes and rewrites `n10/` and `n10.draft.jsonl`. Ids are neutral and shuffled (`c10`-`c..`), never naming the
answer. IBANs (DE, GB, NL, ES, UA) and cards (16 digits) are generated valid, phones in UK, DE, UA, ES, PL and
US-555 shapes; e-mail domains end in `.example.test`; links are `#`.

Checked with a throwaway checker (outside the repo) that ports refsure's `maskPii` verbatim: counts per site,
condition, class and language as above; at most 4 items per base (max 3); no duplicate pages; pages 2.6-3.9 KB;
no URL that loads anything and none of the forbidden names (grep); every gold and alt selector matches exactly
one element whose accessible name equals the stated name, inside the dialog on dismiss pages; every `pii`
string is on the page and gone after masking, and masking changes nothing else (unmasked pages are unchanged);
every `must_not_move` evidence string survives masking and its gold has no masked twin; every
`evidence_removed` evidence string is masked away; no find intent equals a control name (that would be a code
pick); no find page has more than 20 controls; no dismiss overlay is all-vetoed.

## Known limits

- Capture (P2): `orca-native` refuses a set mixing sites, so the capture splits N10 by `site`. Presence page
  text is cleaned at capture with `config.piiMasks` (`presenceInputOf`), so capture must run with masks off and
  let `approve()` apply the masks per mode; otherwise the masks-off half is not raw. `alt` here is in the
  `{selector, name}` shape; `read-refsure-set.ts` reads `alt` as line indices, so the bench reader must use
  `alt_ref` (one item).
- 9 of the 10 `evidence_removed` items on find and dismiss leave two or more options that read the same after
  masking, so refsure's twin rule abstains on any pick; n10-002 (find) differs by hold time only, so the model
  itself must answer `none`. On presence, masks hide which of two values has the asked status; the expectation
  then reads `[iban] shown as verified` against a page holding both a verified and a failed `[iban]`: the right
  answer is to not confirm, but a literal reading may still say yes. That is what Q11 measures, and the
  adjudicator should read these five with that in mind.
- Masking gap found while authoring (refsure `src/egress/pii-masks.ts`, confirmed by running it): two card
  numbers separated only by a space are both left unmasked (the 13-19 digit run never ends), and of two IBANs
  separated by a space the second is left unmasked (the retry at an earlier space keeps the rest unscanned).
  `subtreeText` joins with spaces, so two card or IBAN buttons side by side in a dialog would leak in the
  dismiss `popup` text. The set avoids this (buttons read "Card ..." / "Cuenta ..."), so Q11's byte check will
  not see it; it is a refsure defect to fix or to cover in a later set.
- Class sizes are small (15-25), so per-class readings are descriptive; Q11's verdict pools the 75 and the 15.
- The author is Claude Opus 5.5; all copy and names are invented. Blind agreement is added after labeling.

## Blind label and adjudication (2026-10-16)

Final set: `n10.jsonl` (90 items), byte-equal to `n10.draft.jsonl` because adjudication changed no gold (no item
carries `adjudicated`). Detail per disagreement: `n10.adjudication.md`.

- Labeler: `gemini-3.8-flash-high` through `agy` for all 90 items (A2); no OpenRouter fallback was used. Three
  batches of 30, one per site; batch 02 (dismiss) took 3 `agy` attempts (output-limit cut, then "interrupted").
- Blind agreement against the masks-off gold (the labeler saw raw pages): raw 89/90 (98.9%); by site find 30/30,
  dismiss 29/30, presence 30/30. The masks-on gold was not blind-labelled; it follows from the masking rule.
- Disagreements: 1 (n10-057, dismiss `continue_trap`: draft `none`, label "Continue to seats"); settled keep
  draft. After adjudication: 90/90 settled, 89/90 of the final gold matched the blind label.
- Drops (X8): none.
