# n5

Benchmark protocol 3.5, row N5, as amended by A1. Blind-labelled and adjudicated (sections at the end); not yet captured or frozen.
Files: `n5.draft.jsonl` (760 items), pages under `n5/pages/BBB/` (one folder per base: `before.html` and
`after-1.html`…`after-4.html`).

## What it measures

The `outcome` site (`outcome -- <verb>`, `act --verify`, `outcome --mark/--check`): given the step's intent, the
acted element's line and the page before and after the step, did the step achieve its intent. Gold is `true` or
`false`; only the yes edge acts (`landed`). Every step is a write (a button press that should change data). The set
is held-out data for the outcome row, the false-`landed` danger cell (D299) and `miss_write` on the true items.

| true | landed_toast | 100 | the change in the page's data plus a success toast |
| true | landed_quiet | 100 | the change in the page's data, no message at all |

| true | landed_decoy | 100 | the change, plus an unrelated warning banner (password expiry, maintenance, sync); a toast in half |

| false | still_loading | 60 | a busy strip ("Saving…", progress bar), data unchanged |

| false | no_op | 60 | nothing changed: a "no changes" note, a toast saying so, or (15 items) a page that reads exactly like the before page |
| false | error_page | 60 | 500/502/503/403/404 page, in the site's chrome (60%) or a bare server page |

True 400, false 360 (danger-eligible 360, `danger_eligible: true`). Bases 200: 180 hold 2 true + 2 false afters of one
before page (two different false conditions), 20 hold 2 true afters. So a base holds at most 4 items and at most 2
danger-eligible ones (danger m = 2, 180 danger groups). Items are shuffled with a fixed seed before ids are given, so
a labelling batch does not see one base's items side by side.

Languages (page language): en 382, uk 188, de 64, es 66, pl 60. Of the 378 non-English items, 124 carry an English
intent on a translated page (`intent_lang: "en"`), the rest an intent in the page's language. By condition
(en uk de es pl): toast 57 25 8 5 5, quiet 48 24 7 11 10, confirm 45 26 9 10 10, decoy 50 25 10 8 7, validation 31 16
3 7 3, loading 28 14 6 6 6, wrong item 32 14 5 5 4, modal 30 16 4 5 5, no-op 32 15 7 3 3, error page 29 13 5 6 7.

## Item fields

`id, page, site ("outcome"), lang, intent_lang, source ("synthetic"), condition, base, template, kind, risk ("write"),
before {page, at}, after {page, at}, acted_element {selector, role, name, ordinal}, input {intent, acted, before,
after}, input_provisional, gold, alt ([]), danger_eligible, why`.

- `page` = `before.page`. `at` is the URL path (with query) the page must be served at; before and after often share
  it (an in-place write) and differ when the step navigates (`landed_confirm`) or ends on an error page. The capture
  mounts each page file at its `at` (the page server's `mount`), so the `url:` line reads like a real site, not like
  `after-2.html`.
- `acted_element` names the pressed button in the before page: a neutral `#c<n>` id, its role and visible name, and
  its ordinal among same-role, same-name controls (news-newsletter and admin-role have several equal names).
- `input` is refsure's `OutcomeInput` (`intent`, `acted`, `before`, `after`) built by this generator's own text reading
  (`input_provisional: true`). The native capture (P2) replaces `acted` with refsure's v1 line for the acted element and
  `before`/`after` with `outcomeSide` of each page as Orca reads it; `intent` is final.
- No item sets `--expect-text` or `--expect-url`, so refsure's landed-by-code rule never fires and no item is settled
  by code at capture (X5): the danger pool stays 360 (P3b floor 345).

## Generator

    node tools/bench/sets/gen/n5.mjs

Plain Node, no dependencies, seed `refsure-bench-n5-20261016`; two runs give byte-equal output. Files:
`n5.mjs` (plan, after-page conditions, output), `n5-shell.mjs` (chrome, controls, overlays, error pages),
`n5-lang.mjs` (shared wording in 5 languages), `n5-lib.mjs` (seeded randomness, text reading),
`n5-templates.mjs` and `n5-tpl-*.mjs` (one per template). `n5-lib.mjs` and `n5-lang.mjs` were kept from an earlier,
unfinished author of this set (written before A1); no partial output existed. All brands, people, places and
addresses are invented; e-mail addresses use `example.test`; links are relative; no page loads anything (no script,
image, font or external stylesheet).

Checks run on the draft (throwaway checker outside the repo): counts per condition and gold as above; every base
<= 4 items and <= 2 false; 960 page files, no two byte-equal; largest page 6.2 KB; no `http(s)://`, `src=`, `url(`
or forbidden company names in pages or items; every acted selector matches exactly one `button` in its before page,
with the stated name and ordinal.

## Known limits

- The provisional input texts are this generator's reading (every `<option>` of a select is listed, input values are
  shown); the frozen inputs come from the native capture, and the counts are re-derived after it (3.1).
- Two items of a base share a before page and differ only in the after page; the group is the base.
- Error pages (60) and the 15 silent no-op afters are easy for a careful reader; the hard false items are
  wrong_item (near twins), still_loading and the validation errors whose message is small.
- landed_decoy's banners are warnings, not errors about this step; landed_confirm sometimes changes the URL in a
  telling way (`?saved=1`, `/complete`), as real sites do.
- One language per page; uk, de, es and pl copy was written by the author (not a native speaker review).
- Blind agreement and adjudication results are added here after P1 (3.5).

## Blind label and adjudication (2026-10-16)

- Labeler models: `gemini-3.8-flash-high` through `agy` for all 760 items (A2); the OpenRouter fallback
  (`google/gemini-3.1-pro-preview`) was never used. 76 batches of 10, each in its own directory holding only
  `items.jsonl` and `schema.json`. Retries: three batches hit one 503 "Eligibility check failed: UNAVAILABLE" each,
  four re-ran once because the answer came back inside a markdown fence; every retry succeeded.
- Deviation from A2's batch size: A2 caps a batch at 50; these used 10 (smaller, within the cap). A first run at 25
  per batch returned empty answers (`agy` tried to run a command and headless mode denied it); that run was wiped,
  a "you have no tools in this task" line added, and the batch size cut. No label of the wiped run was kept.
- `n5.blind.jsonl` holds only `id`, `question` (the outcome site's wording with intent, acted line and URLs filled
  in), `before` and `after` (page HTML); no gold, `why`, `condition` or note.
- Blind agreement, raw: 759 of 760 (0.9987). By gold: true 400/400, false 359/360. By condition every one agrees
  fully except `wrong_item` 59/60.
- Adjudication (`n5.adjudication.md`, a fresh Claude Opus 5.5 agent): keep draft 1, take label 0, drop 0. The one
  disagreement (n5-167, wrong_item) is settled by the page's unchanged "People with access" list. After
  adjudication the blind labels agree with the final gold on the same 759 of 760 (no gold changed); the final gold
  is settled on 760 of 760.
- Drops (X8): none. `n5.jsonl` is byte-equal to `n5.draft.jsonl` (sha256
  99860c027458eb1b0b70beac0bd88dde321c3d39a872d979210df3ac32983fe0); no item carries `adjudicated`.
- Limit: the adjudicator is the author's model family (T3); near agreement on a single labeler is not proof that
  the hard false items (near twins, small validation messages) are hard for a model arm.

## Floors (3.6)

Pre-capture counts; P3 re-derives them on the post-capture file. Outcome is not a candidate site, so X1 does not
apply, and no item sets `--expect-text` or `--expect-url`, so none is expected to be settled by code (X5).
- E99 (outcome, yes edge): 400 true x 0.90 = ~360 acted; n_eff ~313 at 3.6's deff 1.15 (~327 at this set's m = 2,
  deff 1.1): holds (>= 299). `miss_write` is read on the same 400 true items.
- D299 danger: 360 false items, n_eff floor(360 / 1.1) = 327: holds (>= 299).
- A1 / P3b floor for N3-N6: danger-eligible pool 360 >= 345: holds, with 15 items of reserve (no drop used any).
